1. What is one aspect of the Continuous Delivery Pipeline?
A. Continuous Experimentation
B. Continuous Security
C. Continuous Delivery
D. Continuous Integration
Answer: D
Explanation:
The four aspects of the SAFe Continuous Delivery Pipeline are Continuous Exploration, Continuous Integration, Continuous Deployment, and Release on Demand.

2. What can impede the progress of a DevOps transformation the most?
A. When there is no DevOps team
B. Lack of funding for CI/CD pipeline tools
C. When various groups in the organization have different directions and goals
D. When teams use frequent retrospectives
Answer: C
Explanation:
DevOps requires the organization to work toward common goals across the value stream. Misaligned groups, goals, and priorities create organizational silos and are a major impediment to transformation.

3. Which statement describes what could happen when development and operations do not collaborate early in the pipeline?
A. Flow times are reduced
B. Automation of integration test is not possible
C. Teams build things quickly but build the wrong things
D. Surprises are found in deployment that lead to significant rework and delay
Answer: D
Explanation:
Poor collaboration between development and operations can result in problems being discovered late, particularly during deployment. This creates rework, delays, and deployment risk.

4. What is one benefit of DevOps?
A. Fewer defects
B. Tightly coupled architecture
C. Increased batch size
D. Better alignment between strategy and execution
Answer: A, D
Explanation:
DevOps improves quality and alignment. SAFe specifically associates successful DevOps with reduced defects/failures and better organizational alignment.

5. What marks the beginning of the Continuous Delivery Pipeline?
A. A committed user story
B. A checked-in change
C. A committed Feature
D. An idea
Answer: D
Explanation:
The Continuous Delivery Pipeline guides functionality from ideation through on-demand release. Continuous Exploration begins with identifying and understanding opportunities.

6. Feature toggles are useful for which activity?
A. To decouple deployment from release
B. To accelerate the deployment process
C. To enable continuous code integration
D. To enable continuous testing
Answer: A
Explanation:
Feature toggles allow code to be deployed without necessarily making the functionality available to users. This separates deployment from release.

7. What organizational anti-pattern does DevOps help to address?
A. Organizations that make decisions along functional lines
B. Teams that are isolated and working within functional areas (e.g., business, operations, and technology)
C. Too much focus on centralized planning
D. Walls of confusion between Customers and the business
Answer: B
Explanation:
DevOps breaks down organizational silos and encourages development, operations, business, security, and other groups to collaborate across the value stream.

8. Value flows through which aspect in the Continuous Delivery Pipeline?
A. Monitor
B. Develop
C. Research
D. Continuous Integration
Answer: D
Explanation:
Continuous Integration is one of the four aspects of the Continuous Delivery Pipeline.

9. Which technical practice incorporates build-time identification of security vulnerabilities in the code?
A. Application security
B. Threat modeling
C. Penetration testing
D. Dynamic code analysis
Answer: A
Explanation:
Application security practices integrate security into development and can identify vulnerabilities during the build process. Dynamic analysis generally examines an application while it is running.

10. Ensuring that security controls such as threat modeling, application security, and penetration testing are in place throughout the Continuous Delivery Pipeline is an example of which stabilizing skill?
A. Security Operations
B. Continuous security monitoring
C. Design for operations
D. Failover disaster recovery
Answer: B
Explanation:
Continuous security monitoring helps ensure security controls remain effective throughout the pipeline rather than being treated as a one-time activity.

11. Scanning application code for security vulnerabilities is an important step in which aspect of the Continuous Delivery Pipeline?
A. Release on Demand
B. Continuous Integration
C. Continuous Exploration
D. Continuous Deployment
Answer: B
Explanation:
Code scanning and automated quality/security checks are integrated into the Continuous Integration process.

12. What should be measured in a CALMR approach to DevOps?
A. Deployment frequency
B. Everything
C. Flow, quality, and value
D. Mean time to restore
Answer: C
Explanation:
Measurement in CALMR focuses on meaningful measures of flow, quality, and value, rather than simply measuring activity. CALMR itself stands for Culture, Automation, Lean Flow, Measurement, and Recovery.

13. What is an element of CALMR?
A. Recovery
B. Metrics
C. Compliance
D. Application security
Answer: A
Explanation:
The five CALMR elements are Culture, Automation, Lean Flow, Measurement, and Recovery.

14. What is the purpose of Value Stream Mapping?
A. To create an action plan for continuous improvement
B. To understand the priorities of the Product Owner (PO)
C. To deliver incremental value in the form of working tested software and systems
D. To create an understanding of the budget
Answer: A
Explanation:
Value Stream Mapping identifies delays, bottlenecks, and opportunities for improvement and provides a basis for improving value flow.

15. What does Value Stream Mapping help reveal in the Continuous Delivery Pipeline?
A. DevOps practices that will improve the Value Stream
B. Where automation is needed
C. Bottlenecks to the flow of value
D. Who is responsible for optimizing the Value Stream
Answer: C
Explanation:
A key purpose of mapping is to visualize delays and identify bottlenecks and inefficiencies in the delivery process.

16. What is true about the Critical Flow Properties portion of the DevOps Transformation Canvas?
A. It captures the lowest priority improvement items
B. It captures the flow properties that are most in need of improvement
C. It captures the work-in-process (WIP) limits that should be applied to the Value Stream
D. It captures the people who need to improve the flow properties
Answer: B
Explanation:
Critical Flow Properties identify the flow characteristics that need the greatest improvement.

17. What is the first area that should be identified in Value Stream Mapping?
A. Active Time, Flow Time, and Percent Complete and Accurate (%C&A)
B. The steps
C. The bottlenecks
D. The people who supervise the work
Answer: B
Explanation:
The current-state map first identifies the steps in the value stream. Metrics such as Flow Time, Active Time, and %C&A are then applied to those steps.

18. Which metric reflects the quality of output at each step in the Value Stream?
A. Percent Complete and Accurate (%C&A)
B. Flow Efficiency
C. Code quality
D. Active Time
Answer: A
Explanation:
%C&A measures how often work moves through a step correctly without requiring rework.

19. What does Flow Efficiency measure in the Value Stream?
A. The percentage of time spent on non-value-added activities
B. The percentage of time spent on manual activities
C. The percentage of time spent on value-added activities
D. The percentage of time spent on delays to the number of processes in the Value Stream
Answer: C
Explanation:
Flow Efficiency measures the proportion of total flow time that is spent performing value-added work rather than waiting.

20. What should the team be able to do after current-state mapping?
A. Identify those responsible for the biggest bottlenecks in the process
B. Define Enabler Features that will improve the Value Stream
C. Describe the biggest bottlenecks in the delivery pipeline
D. Define a plan to reduce the lead time and increase Active Time
Answer: C
Explanation:
Current-state mapping provides a shared understanding of the existing pipeline and makes the major bottlenecks and delays visible.

21. Which steps in the value stream should be the main focus when prioritizing improvement items?
A. Steps with a long Active Time
B. Steps with short Active Time and high %C&A in the future-state map
C. Steps with a high Flow Efficiency
D. Steps with low Percent Complete and Accurate (%C&A) and short Active Time in the current-state map
Answer: D
Explanation:
Low %C&A means rework is likely, while short Active Time compared with overall flow time can indicate significant waiting/delay. These are strong candidates for improvement.

22. What is one of the top advantages of mapping the current state of the delivery pipeline?
A. To achieve a collective understanding and consensus around problems
B. To help identify and make short-term fixes
C. To identify some of the processes within the delivery pipeline
D. To help with incremental software delivery
Answer: A
Explanation:
One of the most important benefits is creating a shared understanding of how value actually flows and where the problems are.

23. In which activity are specific improvements to the Continuous Delivery Pipeline identified?
A. Future-state Value Stream Mapping
B. Value Stream identification
C. Problem-Solving Workshop
D. Impact mapping
Answer: A
Explanation:
Future-state mapping describes the desired improved flow and identifies specific opportunities for improvement.

24. Which statement illustrates the biggest bottleneck?
A. WT = 6 days, AT = 5 days, %C&A = 100%
B. WT = 1 day, AT = 0.5 day, %C&A = 90%
C. WT = 10 days, AT = 0.5 day, %C&A = 100%
D. WT = 5 days, AT = 2.5 days, %C&A = 100%
Answer: C
Explanation:
The biggest bottleneck is the step with the greatest waiting/delay relative to the actual active work. C has 10 days of waiting time versus only 0.5 day of active time, making the delay particularly severe.

25. The Continuous Exploration aspect primarily supports which key stakeholder objective?
A. Alignment
B. Research and development
C. Business value
D. Hypothesize
Answer: A
Explanation:
Continuous Exploration focuses on understanding market/customer needs and aligning stakeholders around what should be built.

26. The DevOps Health Radar aligns the four aspects of the Continuous Delivery Pipeline to which four stakeholder concerns?
A. Alignment, quality, time-to-market, business value
B. Exploration, integration, development, reflection
C. Portfolio, Solution, ART, team
D. Productivity, efficiency, speed-to-market, competitive advantage
Answer: A
Explanation:
The four pipeline aspects address different stakeholder concerns: alignment, quality, time-to-market, and business value.

27. How is Lean UX used in Continuous Exploration?
A. To validate the return on investment
B. To automate the user interface scripts
C. To identify minimum marketable features
D. To create a platform to continuously explore
Answer: C
Explanation:
Lean UX helps teams rapidly explore customer needs and validate solutions, supporting identification of the Minimum Marketable Feature (MMF).

28. Gemba walks are an important competency in support of which activity of the DevOps Health Radar?
A. Collaborate and Research
B. Learn
C. Hypothesize
D. Continuous Exploration
Answer: B
Explanation:
Gemba means going to the actual place where work happens. Gemba walks help teams learn directly from the people and processes involved.

29. In what activity of Continuous Exploration are Features prioritized in the ART Backlog?
A. Research
B. Finalize
C. Synthesize
D. Hypothesize
Answer: B
Explanation:
During Finalize, the findings from exploration are turned into prioritized Features for the ART Backlog.

30. Weighted shortest job first (WSJF) is applied to backlogs to identify what?
A. Relative economic value
B. Epics, Features, and Capabilities
C. User business value
D. Proxy for job size
Answer: A
Explanation:
WSJF is a prioritization method that compares the relative economic benefit of jobs against their relative size/duration, helping identify which work should be done first.

31. Where do Features go after Continuous Exploration?
A. Into the Portfolio Backlog, where they are then prioritized
B. Into Continuous Development, where they are implemented in small batches
C. Into Continuous Integration, where they are deployed with feature toggles
D. Into Continuous Integration, where they are then split into Stories
Answer: B
Explanation:
Once Features have been explored and prioritized, they move into development, where teams implement them incrementally.

32. When does the Continuous Integration aspect of the Continuous Delivery Pipeline begin?
A. When code is checked in to version control
B. When a User Story has satisfied its definition of done
C. When a Feature has been pulled for work
D. When the Team Backlog has been refined
Answer: A
Explanation:
Continuous Integration starts when developers check code into version control, triggering automated build and test activities.

33. What work is performed in the Build activity of the Continuous Delivery Pipeline?
A. Code review
B. Compile
C. Code
D. Automated acceptance testing
Answer: B
Explanation:
The Build activity compiles/packages the source code and produces a build artifact that can proceed through subsequent testing.

34. What is a consequence of working in isolation on long-lived code branches?
A. Deployments will fail
B. Rollbacks will be difficult
C. Trunk/main will not always be in a deployable state
D. End-to-end tests will fail
Answer: C
Explanation:
Long-lived branches increase integration risk. Changes can diverge significantly, meaning the main/trunk branch may no longer be continuously deployable.

35. What is one reason for test data management?
A. To automate provisioning data to an application in order to set it to a known state before testing begins
B. To truncate data from the database to enable fast-forward recovery
C. To provide a viable option for disaster-recovery management
D. To track the results of automated test cases for use by corporate audit
Answer: A
Explanation:
Automated test data management allows tests to begin from a known, repeatable state, improving reliability and repeatability.

36. Continuous Deployment enables which key business objective?
A. Time-to-market
B. Manage technical debt
C. Release continuously
D. Business value
Answer: A
Explanation:
Continuous Deployment reduces the time required to move validated changes toward production, supporting faster time-to-market.

37. Which practice helps developers deploy their code into production?
A. Self-service deployment
B. Deployment automation
C. Infrastructure as code
D. Continuous Deployment
Answer: A
Explanation:
Self-service deployment gives authorized developers/teams the ability to initiate deployments without relying on a separate operations team for every deployment.

38. What is one potential outcome of the Verify activity of the Continuous Delivery Pipeline?
A. Fix a broken build
B. Roll back a failed deployment
C. Analyze regression testing results
D. Capture usage metrics from a canary release
Answer: C
Explanation:
Verify focuses on validating that the deployed solution works as expected, including analyzing automated regression and other test results.

39. Why is hypothesis evaluation important when analyzing data from monitoring systems in the Release on Demand aspect?
A. It helps link objective production data to the hypothesis being tested
B. It helps operations teams know where to apply emergency fixes
C. It helps quickly create balanced scorecards for stakeholder review
D. It helps define the minimum viable product (MVP)
Answer: A
Explanation:
Hypothesis evaluation connects actual production/usage data with the original hypothesis, allowing teams to determine whether the expected business or customer outcome occurred.

40. Which practice appears under the Respond activity?
A. Rollback
B. Service virtualization
C. Site Reliability
D. Telemetry
Answer: A
Explanation:
Rollback is a response technique used when a production release causes unacceptable problems.

41. Which teams should coordinate when responding to production issues?
A. Teams across the Value Stream
B. Support teams and Dev teams
C. SRE teams and System teams
D. Dev teams and Ops teams
Answer: A
Explanation:
DevOps emphasizes end-to-end collaboration across the value stream, rather than limiting incident response to a particular functional group.

42. What triggers the Release activity?
A. Change validated in staging environment
B. Business decision to go live
C. Successful user acceptance tests
D. Successful deployment to production
Answer: B
Explanation:
Release on Demand is driven by the business decision to make the solution available to users. Deployment and release are deliberately separated.

43. What is a possible outcome of the Release activity?
A. A Solution is made available to internal users
B. A Solution is migrated to the cloud
C. A Solution infrastructure is provisioned
D. A Solution is deployed to production
Answer: A
Explanation:
Release makes functionality available to users. Deployment to production is a separate pipeline activity; a release can also be limited to a particular group of users.

44. A canary release involves making a Solution available to whom?
A. Internal users only
B. External users only
C. Users conducting User Acceptance Testing
D. Any subset of users
Answer: D
Explanation:
A canary release exposes the new version to a small subset of users before expanding availability to everyone.

45. When should teams use root cause analysis to address impediments to continuous delivery?
A. During Iteration Planning
B. During Inspect & Adapt (I&A)
C. During the management review and problem-solving portion of PI Planning
D. During the Iteration Retrospective
Answer: B
Explanation:
Inspect & Adapt includes structured problem solving, where teams identify systemic problems, analyze their root causes, and develop improvement actions. This supports continuous improvement of the delivery pipeline.
